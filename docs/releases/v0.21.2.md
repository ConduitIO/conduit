# Conduit v0.21.2

A patch release on the v0.21 line. It replaces v0.21.1, which was tagged but never built: its release
workflow failed on a compile error, so no binaries, images or GitHub release exist for it. Everything v0.21.1
was meant to carry is in this release, except the arch-v2 boot-path status change (#3131), which was reverted
because it broke the build and will land again separately.

If you run v0.21.0, upgrade. It refuses to start any pipeline that has no `dead-letter-queue` block, with
`pipeline.dlq_not_recoverable`.

If you run v0.20.6, see its release notice: it has data regressions as well as this refusal. Go back to
v0.20.5 or move to v0.20.7 when it is out. To move to v0.21 instead, read the breaking changes in the
[v0.21.0 notes](v0.21.0.md) first (API bound to localhost with a token off loopback, `env.allow`, file,
JavaScript and egress allowlists) and the file position note under "Behaviour to know about" below.

## Fixed

- **70aabfc** — start pipelines that use the default DLQ again. v0.20.6 and v0.21.0 refused every pipeline
  whose DLQ was `builtin:log` without `payload: true`, which is the default. The default DLQ never receives a
  record: with `window-size: 1` and `window-nack-threshold: 0`, the first nack stops the pipeline and the
  record is not acked, so it is redelivered after a restart. A log DLQ without `payload: true` is now refused
  only when it does receive records (`window-nack-threshold` above 0, or `window-size: 0`), which is the case
  where a nacked record would be acked with only hashes of it kept.
- **70aabfc** — log full records in the `generator-log` template. The log connector logs only hashes by
  default since v0.8.0, so the template showed nothing readable. It sets `payload: "true"` on its synthetic data.

## Behaviour to know about

- The built-in log connector is metadata-only by default (since `conduit-connector-log` v0.8.0). As a
  destination it logs hashes of the key and position, not the record. Set `payload: "true"` to log full
  records, and only on data you are allowed to write to logs.
- The built-in file source (`conduit-connector-file` v0.11.0) holds back a last line that has no trailing
  newline until the newline arrives, so a half-written line is never emitted. Set `quietPeriod` to emit an
  unterminated last line after the file has been quiet for that long. This shipped in v0.21.0.
- A file source position written by v0.10.x (Conduit v0.20.x) is a bare offset with no file identity. v0.11.0
  accepts it if it is within the file and follows a newline, with a `FILE_POSITION_UNVERIFIABLE` warning;
  otherwise the source refuses to start with that code. If the file was rotated during the upgrade, the
  first offset bytes of the new file are skipped, so do not rotate files while upgrading. After the first
  record the position is in the new format, which v0.20.x cannot read: going back to v0.20.x needs the
  pipeline's position reset.
