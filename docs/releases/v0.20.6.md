# Conduit v0.20.6 release notes

**Security release** · draft, not yet released

Conduit v0.20.6 is a security release for the v0.20 line. It backports the API access controls
from v0.21.0 and changes defaults, so read the notes below before upgrading. It contains no other
changes.

## Security: the API is no longer open by default (breaking)

Fixes [GHSA-v79j-j88p-m4ff](https://github.com/ConduitIO/conduit/security/advisories/GHSA-v79j-j88p-m4ff)
(critical; affects v0.20.5 and earlier, fixed in this release and v0.21.0). Before this release the HTTP
and gRPC APIs listened on all interfaces with no authentication, and the HTTP API could be driven by
any web page the user visited, including through DNS rebinding. Anyone who could reach the API could
create and start pipelines, read pipeline configuration and make Conduit read files, open connections
and run plugins on the host. **Upgrade, and if the API was reachable from a network or a browser
you do not control, rotate every credential that appears in your pipeline configuration.**

What changes, and what you may need to do:

- **Loopback by default.** `api.http.address` and `api.grpc.address` default to `127.0.0.1:8080` and
  `127.0.0.1:8084`. If you reach Conduit from another host, set a token (below) and an explicit address.
- **A token is required off loopback.** Binding either API to a non-loopback address (`:8080`,
  `0.0.0.0:8080`, a LAN address) makes Conduit exit at startup with `api.token_required` unless
  `api.token-file` (`CONDUIT_API_TOKEN_FILE`) or `api.token` (`CONDUIT_API_TOKEN`) is set. The token
  must be at least 16 characters.
- **Token gate.** With a token set, HTTP, gRPC (including reflection), `/metrics` and the inspector
  WebSocket require `Authorization: Bearer <token>`, on loopback too. `/healthz`, `/readyz` and the
  gRPC health check stay open. The CLI and `conduit mcp` read the token from `--api.token-file`
  (`--api-token-file` for `mcp`), `CONDUIT_API_TOKEN_FILE` or `CONDUIT_API_TOKEN`. Point Prometheus
  at `/metrics` with a bearer token.
- **Browser protections.** Requests with an `Origin` that is neither allowlisted
  (`api.http.cors.allowed-origins`) nor the API's own origin get `403`, on every method. `POST`, `PUT`,
  `PATCH` and `DELETE` requests with a body must be `application/json` (`415` otherwise). On a loopback
  bind the `Host` header must be `localhost`, `127.0.0.1`, `[::1]` or listed in
  `api.http.allowed-hosts` (`403` otherwise). Scripts that post `text/plain` or form bodies, and
  setups that reach a loopback-bound Conduit through another host name, need a one-line change.
- **Connector utilities server** binds `127.0.0.1` instead of all interfaces.
- **Container image.** Runs as uid/gid 10001 instead of root and listens on `0.0.0.0` inside the
  container, so it needs `CONDUIT_API_TOKEN` or `CONDUIT_API_TOKEN_FILE`. Publish with
  `-p 127.0.0.1:8080:8080`, not `-p 8080:8080`. A volume written by an older image is owned by root:
  run `chown -R 10001:10001` on it once.
- **Built-in UI.** With a token set the UI asks for it, keeps it in `sessionStorage` for the tab,
  and asks again if the API rejects it. The inspector WebSocket carries it as a subprotocol
  (`conduit.token.<base64url>`), never in the URL.
- **Visibility.** `conduit_api_rejected_requests_total{code}` counts refused requests; rejection
  warnings are rate limited to one line per code every 10 seconds.

New error codes: `api.token_required`, `api.token_invalid`, `api.unauthenticated`,
`api.origin_forbidden`, `api.host_forbidden`, `api.content_type_unsupported`. Runbook and migration
steps: [API hardening](../operations/api-hardening.md).
