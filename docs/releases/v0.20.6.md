# Conduit v0.20.6

v0.20.6 is a patch release for the v0.20 line. It closes a set of exposures found in an internal
audit: an unauthenticated API on all interfaces, environment and file exfiltration through the API,
server-side request forgery, and record values written into logs and errors. Most fixes change a
default, so read the list below before you upgrade. A security advisory accompanies this release.

## Fixed

- bind the API to localhost by default and require a token off-loopback. A listener on any other
  address rejects requests without a token, and origin, host, and UI-token checks plus
  per-connection utilities-server auth close the remaining unauthenticated paths.
- restrict plugin environment and file and JavaScript access to allowlists. Plugins and processors
  receive only the variables named in `env.allow`, and the file connector and the JavaScript
  processor read, write, and `require` only within configured directories.
- guard outbound HTTP at dial time against the egress allowlist, closing server-side request forgery
  from connectors.
- make the log connector metadata-only by default. Record payload values are no longer written; keys
  and positions are logged as salted hashes. Set `payload: true` to restore full contents.
- follow complete lines only and fail loudly on rotation. The file source no longer emits a partial
  line on shutdown, and a rotated file it cannot read fails the pipeline instead of silently
  skipping records.
- refuse to start a pipeline with no recoverable DLQ (`pipeline.dlq_not_recoverable`). A log DLQ
  without `payload: true` no longer counts as a place to put undeliverable records.
- fail loudly when the replication slot no longer covers the saved position. The Postgres source
  (v0.14.6) refuses to resume instead of silently losing data; set `logrepl.allowWALGap` to accept
  the gap explicitly.
- bump the Go toolchain to 1.26.10 for GO-2026-6809, a stdlib `crypto/x509` vulnerability reachable
  through the schema registry trust path.
