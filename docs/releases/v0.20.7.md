# Conduit v0.20.7

A patch release on the v0.20 line. **If you run v0.20.6, upgrade.** v0.20.6 has four regressions that v0.20.5 did not
have. Two of them can change record data without an error. v0.20.7 also fixes two older bugs that v0.20.5
had, so upgrade from v0.20.5 too.

## What was wrong in v0.20.6

The v0.20.6 dependency bump (built-in log v0.7.7, file v0.10.11) also moved `conduit-commons` from v0.7.2 to
v0.8.0 and the connector SDK from v0.14.4 to v0.15.0. Both of those releases predate fixes that v0.20.5
already carried, so v0.20.6 brought the bugs back:

- **Fan-out branches could see each other's changes.** `StructuredData.Clone` was shallow again
  (`conduit-commons#336`). When a pipeline fans a record out to several destinations and a processor on one
  branch mutates a nested value (for example a JavaScript processor changing an array), the other branches
  could receive the mutated value.
- **Avro encoding could produce wrong output.** `Serde.Marshal` mutated its input (`conduit-commons#342`), so a
  value shared between two encodes could come out changed, and named Avro types were shared between subjects
  (`conduit-commons#309`), so two subjects that reuse a type name with different definitions could encode with
  the wrong one.
- **SIGTERM could hang** with a batching standalone destination after the pipeline drained (#3092,
  `conduit-connector-sdk#414` and `#416`). `kill -9` remained safe; a graceful stop did not finish.
- **Every pipeline without a `dead-letter-queue` block was refused at start** with
  `pipeline.dlq_not_recoverable`, including the hello-pipeline example and the template gallery.

If you ran v0.20.6 with fan-out and processors that modify nested values, or with Avro encoding of records
that share values or type names across subjects, check the affected destinations.

## Fixed

- **98c95b5** — bump `conduit-commons` to v0.8.3, which carries the v0.7.2 data fixes (deep
  `StructuredData.Clone`, `Serde.Marshal` without input mutation, per-Serde named types).
- **98c95b5** — bump `conduit-connector-sdk` to v0.16.2, restoring the #3092 SIGTERM fix.
- **98c95b5** — start pipelines that use the default DLQ again. The default DLQ (`builtin:log`,
  `window-size: 1`, `window-nack-threshold: 0`) never receives a record: the first nack stops the pipeline and
  the record is not acked, so it is redelivered after a restart. A log DLQ without `payload: true` is now
  refused only when it does receive records (threshold above 0, or `window-size: 0`).
- **98c95b5** — apply that refusal to every spelling of the log connector. `builtin:log@v0.8.0`,
  `builtin:log@latest`, a bare `log` and `standalone:log` were not refused, so with a threshold above 0 they
  acked nacked records while keeping only hashes of them.
- **98c95b5** — match goccy/go-json v0.11 byte output in the JSON size estimator. v0.20.6 moved to go-json
  v0.11, which writes `\b` and `\f` as short escapes and drops the leading zero of a negative exponent, so
  the estimate no longer matched the encoded size.
- **98c95b5** — log full records in the `generator-log` template, which showed only hashes.
- **19a5a4a** — copy the batch before the batch middleware reads ahead (`conduit-connector-sdk#422`, in SDK
  v0.16.2). With `sdk.batch.*` set, the SDK read the next batch while the previous one was still in flight,
  so a connector that reused its returned slice could overwrite records whose later positions were then
  acked. v0.20.5 had this too. The built-in connectors do not reuse their slices; standalone connectors
  built with an earlier SDK should be rebuilt.
- **76a663a** — copy the file payload per record in the built-in generator (v0.10.9). In file mode every
  record, and both Before and After of an update, shared one buffer, so a processor that changed one
  record's payload in place changed all of them. v0.20.5 had this too.

Still present from v0.20.6 (the release gate checks that each one is still in the build):

- **19f8c95** — bind the API to localhost by default and require a token off-loopback
- **919185b** — restrict plugin environment and file and JavaScript access to allowlists, guard outbound
  HTTP at dial time against the egress allowlist, and refuse a pipeline with no recoverable DLQ
- **27f39e7** — make the log connector metadata-only by default
- **e9dab5b** — follow complete lines only and fail loudly on rotation (file connector)
- **213daec** — bump the Go toolchain to 1.26.10 for GO-2026-6809
- **df7230f** — fail loudly when the replication slot no longer covers the saved position (Postgres)

## Behaviour to know about

- The built-in log connector is metadata-only by default: as a destination it logs hashes of the key and
  position. Set `payload: "true"` to log full records, and only on data you may write to logs.
- v0.20.7 changes no position, state or connector configuration format, so going back to v0.20.6 needs no
  migration (the file connector stays at v0.10.11).
