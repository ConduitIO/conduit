# Conduit v0.21.0 release notes

**Migrate from Kafka Connect, part 1** · draft, not yet released

Conduit v0.21.0 is the first release aimed squarely at teams moving off Kafka Connect. It adds
`conduit migrate kafka-connect`, which turns a Kafka Connect worker and connector config into a
Conduit pipeline plus a compatibility report, and it certifies a first set of connectors for that
path: Postgres CDC, MySQL CDC (beta), Elasticsearch/OpenSearch, Kafka→Kafka mirroring, and the S3
sink. It also lands lossless structured values over protocol v3, Protobuf decode, secrets-at-rest,
the processor batch API, and the Python connector SDK GA.

## Security: the API is no longer open by default (breaking)

Fixes [GHSA-v79j-j88p-m4ff](https://github.com/ConduitIO/conduit/security/advisories/GHSA-v79j-j88p-m4ff)
(critical; affects v0.20.5 and earlier, fixed in v0.20.6 and v0.21.0). Before this release the HTTP
and gRPC APIs listened on all interfaces with no authentication, and the HTTP API could be driven by
any web page the user visited, including through DNS rebinding. Anyone who could reach the API could
create and start pipelines, read pipeline configuration and make Conduit read files, open connections
and run plugins on the host. **Upgrade, and if the API was reachable from a network or a browser
you do not control, rotate every credential that appears in your pipeline configuration.**

What changes, and what you may need to do:

- **Loopback by default.** `api.http.address` and `api.grpc.address` default to `127.0.0.1:8080` and
  `127.0.0.1:8084`. If you reach Conduit from another host, set a token (below) and an explicit address.
- **A token is required off loopback.** Binding either API to a non-loopback address (`:8080`,
  `0.0.0.0:8080`, a LAN address) makes Conduit exit at startup with `api.token_required` unless
  `api.token-file` (`CONDUIT_API_TOKEN_FILE`) or `api.token` (`CONDUIT_API_TOKEN`) is set. The token
  must be at least 16 characters.
- **Token format.** The token must not contain whitespace or control characters, and a
  whitespace-only `api.token` is rejected (`api.token_invalid`) instead of being read as "no token".
  A token file's trailing newline is still trimmed.
- **Token gate.** With a token set, HTTP, gRPC (including reflection), `/metrics` and the inspector
  WebSocket require `Authorization: Bearer <token>`, on loopback too. `/healthz`, `/readyz` and the
  gRPC health check stay open; with a token set, `/readyz` returns only ready or not-ready to a caller
  without the token (the pipeline summary needs it). The CLI and `conduit mcp` read the token from `--api.token-file`
  (`--api-token-file` for `mcp`), `CONDUIT_API_TOKEN_FILE` or `CONDUIT_API_TOKEN`. Point Prometheus
  at `/metrics` with a bearer token.
- **Browser protections.** Requests with an `Origin` that is neither allowlisted
  (`api.http.cors.allowed-origins`) nor the API's own origin get `403`, on every method. `POST`, `PUT`,
  `PATCH` and `DELETE` requests with a body must be `application/json` (`415` otherwise). On a loopback
  bind the `Host` header must be `localhost`, `127.0.0.1`, `[::1]` or listed in
  `api.http.allowed-hosts` (`403` otherwise). Scripts that post `text/plain` or form bodies, and
  setups that reach a loopback-bound Conduit through another host name, need a one-line change.
  The Host check fails closed: an empty `Host`, `localhost.` (trailing dot), loopback aliases other
  than `127.0.0.1` and `::1` (`127.0.0.2`, `[::ffff:127.0.0.1]`) and malformed values are refused;
  list any such name you use in `api.http.allowed-hosts`. The check is off on non-loopback binds.
- **Response headers.** The API and UI send `X-Frame-Options: DENY`, a CSP with
  `frame-ancestors 'none'` and `script-src 'self'`, `nosniff` and `Referrer-Policy: no-referrer`.
  A custom page that embeds the UI in a frame, or injects inline script into it, stops working.
- **Connector utilities server** binds `127.0.0.1` instead of all interfaces.
- **Container image.** Runs as uid/gid 10001 instead of root and listens on `0.0.0.0` inside the
  container, so it needs `CONDUIT_API_TOKEN` or `CONDUIT_API_TOKEN_FILE`. **Because that bind is not
  loopback, the Host check is off in the container and only the token stops DNS rebinding.** The
  token is sent in plaintext without TLS. Publish with `-p 127.0.0.1:8080:8080`, not
  `-p 8080:8080`, and terminate TLS in front of it for any network use. A volume written by an older image is owned by root:
  run `chown -R 10001:10001` on it once.
- **Built-in UI.** With a token set the UI asks for it, keeps it in `sessionStorage` for the tab,
  and asks again if the API rejects it. The inspector WebSocket carries it as a subprotocol
  (`conduit.token.<base64url>`), never in the URL.
- **Visibility.** `conduit_api_rejected_requests_total{code}` counts refused requests; rejection
  warnings are rate limited to one line per code every 10 seconds.

New error codes: `api.token_required`, `api.token_invalid`, `api.unauthenticated`,
`api.origin_forbidden`, `api.host_forbidden`, `api.content_type_unsupported`. Runbook and migration
steps: [API hardening](../operations/api-hardening.md).

## Migrating from Kafka Connect

- **`conduit migrate kafka-connect`.** Reads a Kafka Connect worker and connector config and emits
  Conduit pipeline config plus a compatibility report. Every setting is translated, approximated,
  or flagged as blocking — the command never silently drops config it can't translate. It covers
  Debezium Postgres and MySQL, JDBC source and sink, the S3 sink, Elasticsearch and OpenSearch,
  and Kafka→Kafka (MirrorMaker-style).
- **No re-snapshot for Postgres.** A migrated Postgres pipeline resumes from its Debezium offsets:
  Conduit creates its own replication slot (the fresh-slot strategy) at the imported position.
  v0.21 ships that path for Postgres only; migrations of the other connectors still re-snapshot,
  and offset import for them is v0.22.
- **Debezium-compatible output for Postgres.** An opt-in output mode emits the envelope, topic
  naming, key schema, tombstones, and decimal/time encodings that Debezium consumers expect,
  verified against real Debezium on the same database.

## Certified connectors

Every connector `conduit migrate kafka-connect` emits is certified in this release.

- **Postgres CDC** — Debezium parity plus offset import (fresh-slot), chaos-tested.
- **MySQL CDC (beta)** — the labs `mysql` source, certified as beta.
- **Elasticsearch and OpenSearch** — the sink, certified from labs.
- **Kafka→Kafka** — mirroring with partition, header, and topic preservation, plus a Redpanda
  profile.
- **S3 sink** — format and partitioning parity with the Kafka Connect S3 sink, and the AWS default
  credential chain.

## Notable features

- **Protocol v3 and lossless structured values.** int64, uint64, bytes, and decimal now cross the
  plugin boundary exactly — no 2^53 rounding, no `[]byte`→base64, no `NaN`/`Inf`→string.
- **Protobuf decode** for Confluent Schema Registry (PB-1 to PB-6).
- **Secrets at rest.** `${VAR}` references are no longer stored in plaintext; they are resolved
  when a connector, processor, or DLQ is provisioned.
- **Processor batch API** and a `stateless` declaration, plus processor input isolation that keeps
  DLQ records faithful.
- **Connector observability.** Per-connector record and error counters.
- **Python connector SDK GA.** One merged `conduit.connector` / `conduit.client` distribution, and
  `conduit connector new --lang python`.
- **Catalog.** Public quality tiers and a license scorecard.
- **Engine.** arch-v2 grows toward the single engine, and the benchi regression gate is live.

## Breaking changes: pipeline settings no longer reach the host by default

Settings can arrive over the API, so four things a setting used to reach are now closed unless the
operator opens them in `conduit.yaml`, by flag or by `CONDUIT_*` environment. Pipelines that rely on
any of them stop working after the upgrade until the operator adds the matching key. A refused
setting fails with a coded error that names the key to change. Decision:
[ADR](docs/architecture-decision-records/20261021-deny-by-default-settings-and-outbound-access.md).

| Before | Now | Add to keep the old behavior |
| --- | --- | --- |
| `${VAR}` expanded any environment variable | only names in `env.allow` expand; `${VAR:-x}`, nesting and malformed references are refused | `env.allow: [VAR, ...]` ([runbook](docs/operations/env-allowlist.md)) |
| `webhook.http`, `ollama.request`, `openai.*`, `cohere.*` could reach private, loopback and metadata addresses, followed any redirect and used `HTTP(S)_PROXY` | those addresses are refused at dial time, on every redirect hop; the proxy environment is ignored | `processors.egress.builtin-allow: ["http://127.0.0.1:11434"]` ([runbook](docs/operations/outbound-http-egress.md)) |
| the `file` connector read and wrote any path; the `generator` file format and Postgres TLS file parameters read any file; `custom.javascript` read any `script.path` and had `require()` | confined to `connectors.file.allowed-dirs` (default `<data dir>/files`), `secrets.allowed-dirs` (TLS and credential files; default `<data dir>/secrets` and the system CA directories) and `processors.javascript.allowed-dirs` (default `<data dir>/scripts`, `require()` off) | the directories your pipelines use ([runbook](docs/operations/file-access.md)) |
| built-in connectors connected to any address a setting named, cloud metadata endpoints included | metadata endpoints (`169.254.0.0/16`, `fd00:ec2::/32`, Azure WireServer, `metadata.google.internal`, ... in any encoding or via DNS) are refused; API writers are still trusted to choose other targets. Optional operator allowlist `connectors.egress.allow` | nothing is needed for databases in private ranges; set `connectors.egress.allow` to restrict targets ([runbook](docs/operations/connector-egress.md)) |
| Postgres `passfile`, `servicefile` were accepted inside `secrets.allowed-dirs`; pgx read `~/.pgpass` for API-supplied URLs | `passfile`, `servicefile` and `service` are refused; `passfile`, `sslcert`, `sslkey` default to empty | put the password in the connection string or an allowed `${VAR}` |
| `/run/secrets` was in the default `secrets.allowed-dirs` | removed | name the directory you need in `secrets.allowed-dirs` |
| a connector with a setting that no longer resolved could not be deleted | deleted; the plugin's `deleted` hook is skipped with a warning (plugin-side cleanup, for example a replication slot, is then manual) | fix the setting first if you need the hook to run |
| `conduit-connector-file` created output files 0644 | 0600 (files created by older versions stay 0644: `chmod 600` them) | create the file first, or `chmod` |
| the log connector, and so the default DLQ, logged the whole record | logs a salted hash of the position and key, the operation and an allowlist of safe metadata keys (values of other keys are dropped, the DLQ nack error only as its Go qualifier); `payload: true` logs the record | `payload: true` on the log connector, with the log-access implications |

Embedders get the same controls as `Options.EnvAllow`, `FileAllowedDirs`, `JavaScriptAllowedDirs` and
`BuiltinEgressAllow`.

Known limitation: in pipeline YAML, `$$` is collapsed to `$` by the parser, so `$${VAR}` no longer
works as an escape; it is refused like any other unlisted reference.

## Protocol version 2 deprecation

Protocol v2 remains fully supported and is what existing plugins negotiate. Protocol v3 is used
only when both peers support it. Following the announce → warn → remove policy, protocol v2 will
be deprecated with a warning in v0.22 and removed no earlier than v0.24. No user action is
required for v0.21.

## Migrating

Start with [`conduit migrate kafka-connect`](docs/design-documents/20261012-migrate-kafka-connect.md),
or read the migration command's `--help`. The command prints a compatibility report for every run,
so you can see exactly what translated, what was approximated, and what would block before you
switch.
