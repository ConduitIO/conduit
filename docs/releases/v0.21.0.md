# Conduit v0.21.0

v0.21.0 is a security release. It closes a set of exposures found in an internal audit: an
unauthenticated API on all interfaces, environment and file exfiltration through the API,
server-side request forgery, plaintext SASL credentials, and record values written into logs and
errors. Most of the fixes change a default, so read [Breaking changes](#breaking-changes) before
you upgrade. The same fixes are backported to v0.20.6. A security advisory accompanies this
release.

It also ships the Kafka Connect migration work that has been building all release: `conduit
migrate kafka-connect`, the first set of certified connectors, protocol v3 with lossless
structured values, Protobuf decode, secrets at rest, and the processor batch API.

## Breaking changes

| Change | What to do |
| --- | --- |
| **The HTTP/gRPC API binds to localhost by default.** It no longer listens on all interfaces, and a listener on anything but loopback requires an auth token. | Keep using the default localhost bind, or set a token when you bind the API to a network interface. |
| **`${VAR}` references are allowlisted.** Plugins and processors no longer receive the whole environment; only variables named in the `env.allow` list are passed through. | Add every variable your config expands to the allowlist. |
| **File and JavaScript paths are allowlisted.** The file connector and the `custom.javascript` processor now restrict reads, writes, and `require` to configured directories. | Configure the allowed directories for any path outside the default. |
| **Outbound HTTP is guarded.** Connector egress is enforced at dial time against an allowlist, closing server-side request forgery. | Add each connector's outbound endpoint to the egress allowlist. |
| **The log connector is metadata-only.** It no longer writes record payload values; keys and positions are logged as salted hashes. | Set `payload: true` on the log connector if you need full record contents. |
| **A pipeline with no recoverable DLQ refuses to start** (`pipeline.dlq_not_recoverable`). A log DLQ without `payload: true` no longer counts as a place to put undeliverable records. | Configure a real DLQ, or a log DLQ with `payload: true`. |
| **Kafka refuses SASL without TLS.** A SASL mechanism that would send credentials in plaintext is refused unless `saslAllowPlaintext: true`; `conduit migrate kafka-connect` now blocks `SASL_PLAINTEXT` instead of translating it. | Enable TLS, or set `saslAllowPlaintext` if you accept the exposure. |
| **Postgres refuses a replaced replication slot** (v0.17.5). The source detects a slot recreated under the same name, a restored database, or a changed WAL history, and refuses to resume instead of silently losing data. New error codes: `postgres.source.slot_replaced`, `postgres.source.wal_history_changed`, `postgres.source.slot_identity_check_failed`. | Re-snapshot after a restore; the source tells you when. |

## Security hardening

- **Go 1.26.10**, for GO-2026-6809 (stdlib `crypto/x509`, reachable through the schema registry
  trust path).
- **Errors and logs no longer echo record values.** Record values and keys, request URLs and
  bodies, and registry URLs are redacted, and record positions are logged as salted hashes rather
  than in the clear. This lands across the engine, processors, and built-in connectors.

## Migrating from Kafka Connect

- **`conduit migrate kafka-connect`.** Reads a Kafka Connect worker and connector config and emits
  Conduit pipeline config plus a compatibility report. Every setting is translated, approximated,
  or flagged as blocking — the command never silently drops config it can't translate. It covers
  Debezium Postgres and MySQL, JDBC source and sink, the S3 sink, Elasticsearch and OpenSearch,
  and Kafka→Kafka (MirrorMaker-style).
- **No re-snapshot for Postgres.** A migrated Postgres pipeline resumes from its Debezium offsets:
  Conduit creates its own replication slot (the fresh-slot strategy) at the imported position.
  v0.21 ships that path for Postgres only; migrations of the other connectors still re-snapshot,
  and offset import for them is v0.22.
- **Debezium-compatible output for Postgres.** An opt-in output mode emits the envelope, topic
  naming, key schema, tombstones, and decimal/time encodings that Debezium consumers expect,
  verified against real Debezium on the same database.

## Certified connectors

Every connector `conduit migrate kafka-connect` emits is certified in this release.

- **Postgres CDC** — Debezium parity plus offset import (fresh-slot), chaos-tested.
- **MySQL CDC (beta)** — the labs `mysql` source, certified as beta.
- **Elasticsearch and OpenSearch** — the sink, certified from labs.
- **Kafka→Kafka** — mirroring with partition, header, and topic preservation, plus a Redpanda
  profile.
- **S3 sink** — format and partitioning parity with the Kafka Connect S3 sink, and the AWS default
  credential chain.

## Notable features

- **Protocol v3 and lossless structured values.** int64, uint64, bytes, and decimal now cross the
  plugin boundary exactly — no 2^53 rounding, no `[]byte`→base64, no `NaN`/`Inf`→string.
- **Protobuf decode** for Confluent Schema Registry (PB-1 to PB-6).
- **Secrets at rest.** `${VAR}` references are no longer stored in plaintext; they are resolved
  when a connector, processor, or DLQ is provisioned.
- **Processor batch API** and a `stateless` declaration, plus processor input isolation that keeps
  DLQ records faithful.
- **Connector observability.** Per-connector record and error counters.
- **Python connector SDK GA.** One merged `conduit.connector` / `conduit.client` distribution, and
  `conduit connector new --lang python`.
- **Catalog.** Public quality tiers and a license scorecard.
- **Engine.** arch-v2 grows toward the single engine, and the benchi regression gate is live.

## Protocol version 2 deprecation

Protocol v2 remains fully supported and is what existing plugins negotiate. Protocol v3 is used
only when both peers support it. Following the announce → warn → remove policy, protocol v2 will
be deprecated with a warning in v0.22 and removed no earlier than v0.24. No user action is
required for v0.21.

## Migrating

Start with [`conduit migrate kafka-connect`](docs/design-documents/20261012-migrate-kafka-connect.md),
or read the migration command's `--help`. The command prints a compatibility report for every run,
so you can see exactly what translated, what was approximated, and what would block before you
switch.
