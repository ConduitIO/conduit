# v0.21 JDBC sink parity: Postgres and MySQL destinations

Status: 2026-10-15. Roadmap item: v0.21, "JDBC sink family" (#3006). This page compares the Confluent
`kafka-connect-jdbc` sink (10.9.x) with the two destinations `conduit migrate kafka-connect` emits for it: the
built-in `postgres` destination and `ConduitIO/conduit-connector-mysql`. It records what each destination does
**after** these PRs merge, and what is scoped out of v0.21:

- `ConduitIO/conduit-connector-mysql#193`
- `ConduitIO/conduit-connector-postgres#415`

Before then, the "Bugs fixed" table lists what `main` does instead.

It complements the JDBC sink rows of
[the migrate mapping tables](../design-documents/20261014-migrate-kafka-connect-mapping-and-harness.md#jdbc-sink)
and section 2 of [the certification gaps](v0.21-certification-gaps.md). Where this page and the mapping
tables differ, see _Corrections to the mapping rows_.

Legend: **T** translated (same behavior), **A** approximated (documented difference), **U** unsupported.
**Out** marks a feature scoped out of v0.21. Nothing here is a performance claim.

## Matrix

| Kafka Connect sink | `postgres` destination | `mysql` destination | v0.21 |
| --- | --- | --- | --- |
| `insert.mode=insert` | A: a keyed record upserts (`ON CONFLICT DO UPDATE`); a keyless record is a plain `INSERT` | A: always `INSERT ... ON DUPLICATE KEY UPDATE`; a table without a unique key appends | Kafka Connect fails on a duplicate, Conduit overwrites. Documented |
| `insert.mode=upsert` | T with `pk.mode=record_key`: conflict target is the record key's columns, which need a primary key or unique constraint | A: the conflict is on **any** unique key of the table, and key columns are taken from the payload, not the record key | Done |
| `insert.mode=update` | U | U | **Out**. No update-only mode; an update upserts |
| `pk.mode=none` | A: upserts whenever a key is present | A: upserts on the table's unique keys | Documented |
| `pk.mode=record_key` | T | A (see `upsert`) | Done |
| `pk.mode=record_value`, `pk.fields` | U: the key always comes from the record key | A: the payload values decide the conflict when the fields are the table's unique key | **Out** for `postgres`. A processor that sets `.Key` from payload fields is the recipe |
| `pk.mode=kafka` | U | U | **Out** (topic, partition and offset as the key) |
| `delete.enabled=true` | T: needs a key; deletes the rows matching every key column | T: needs a primary key on the table and every PK column in the record key; integer keys are matched exactly | Done |
| `delete.enabled=false` (the default) | U: deletes are always applied | U: deletes are always applied | **Out** as a setting. Recipe: a `filter` processor on `.Operation == "delete"`. `migrate` reports it as blocking (`kc.default_differs`) |
| Tombstone (null value) as delete | A: only OpenCDC delete records delete | A: same | Documented. A Kafka source maps tombstones per its own settings |
| `auto.create` | U | U | **Out**. Create tables ahead of time. Invariant 6: no inferred DDL |
| `auto.evolve` | U: a field with no column fails the write | U: a field with no column fails the write (`mysql.destination.unknown_column`) | **Out**. Both destinations declare the `reject` schema-evolution policy, which acceptance case DST-07 verifies |
| Mixed field sets in one batch | T: each record is its own statement | T: runs of identical field sets, in order (#222 fixed) | Done. A missing field is not written: the insert gets the column default, an existing row keeps its value. Kafka Connect with schemas writes NULL instead |
| `table.name.format` | A: `table` is a Go template; the result is **one** quoted identifier (a dot is part of the name) | A: `opencdc.collection` only; `db.table` addresses another database | See correction 1 |
| `quote.sql.identifiers` (`always`) | T: always quoted (`pgx.Identifier`) | T: always quoted (backticks) | `never` is A: unquoted Postgres names fold to lower case, quoted ones do not |
| `batch.size` | A: `sdk.batch.size`; one implicit transaction per write | A: `sdk.batch.size`; one transaction per write | |
| `max.retries`, `retry.backoff.ms`, `connection.attempts`, `connection.backoff.ms` | A: pipeline recovery; no retry inside `Write` | A: same | |
| Transaction failure | T: `0, err`, nothing acked, redelivered | T: same (#187 fixed) | Proven by DST-01 to DST-05 |
| Redelivery after crash | Idempotent for keyed upserts; keyless inserts duplicate | Idempotent on a primary or unique key; tables without one duplicate | DST-05 passes with `Idempotence: idempotent` on both |
| Key-changing update | U: the old row stays (postgres#386) | U: the old row stays | **Out** for v0.21 unless #3004 provides the old key. Debezium-format input emits delete plus create and is not affected |
| `fields.whitelist` | U | U | **Out**. Recipe: `field.exclude` |
| `db.timezone`, `timestamp.*`, `date.calendar.system` | type-handling pattern | type-handling pattern | Per the mapping document |
| Integers above 2^53 | T for raw JSON (#402 fixed); structured data is rounded in transit (#3100) | T for raw JSON keys; structured data is rounded in transit (#3100) | #3100 is a platform decision |
| Dialects other than PostgreSQL and MySQL | none | none (MariaDB untested) | **Out**: `kc.connector_class_unsupported` |

## Corrections to the mapping rows

1. **`table.name.format` for `postgres`.** The row says "other `postgres` formats with `${topic}` T". A format
   with a schema prefix (`public.${topic}`) becomes the template `public.{{...}}`, which the destination quotes as
   **one** identifier, so the write fails with "relation does not exist". Proposed: T only without a dot; with a dot,
   A!, with the fix "set `search_path` in the URL and drop the schema from the template".
2. **`pk.mode=record_value` for `mysql`.** It is closer to A than to U: the MySQL destination's conflict comes from
   payload values on the table's unique keys. This is only a status nuance; the reason text should name the
   unique-key condition.
3. **`quote.sql.identifiers`.** `always` (the Kafka Connect default) is T for both destinations once the PRs above
   merge. `never` stays A.
